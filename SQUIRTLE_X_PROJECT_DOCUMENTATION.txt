1. PROJECT OVERVIEW
================================================================================

SQUIRTLE-X is an AI-powered smart water infrastructure management system that
combines real-time simulation, autonomous decision-making, and predictive
intelligence to optimize urban water distribution networks.

The system functions as a digital twin of water infrastructure, capable of:
- Real-time monitoring of pipes, valves, sensors, and water quality
- Autonomous detection and resolution of leaks, blockages, and contamination
- Predictive maintenance alerts for aging infrastructure
- Intelligent water rerouting and tanker dispatch
- Citizen complaint integration with automated response generation

Unlike traditional SCADA systems that only monitor, SQUIRTLE-X actively
intervenes—detecting issues, prioritizing actions, and executing fixes
autonomously through its AI-driven AutoFix engine.


2. PROBLEM STATEMENT
================================================================================

Urban water distribution systems face critical challenges:

INFRASTRUCTURE DEGRADATION
- Aging pipes (50-100 year lifespans) fail unpredictably
- Manual inspections miss hidden leaks between monitoring points
- Corrosion and material fatigue cause sudden ruptures

OPERATIONAL INEFFICIENCY
- Water loss through undetected leaks (20-30% in aging cities)
- Uneven pressure distribution causes supply shortages
- Manual valve adjustments delay emergency response

WATER QUALITY RISKS
- Contamination spreads rapidly through interconnected networks
- pH imbalances and pollution go undetected until citizen complaints
- No automated isolation or treatment redirection

CITIZEN DISCONNECT
- Communities lack real-time visibility into water issues
- Complaint systems are manual, slow, and non-integrated
- No feedback loop between citizen reports and infrastructure response


3. SOLUTION
================================================================================

SQUIRTLE-X addresses these challenges through three core pillars:

AUTONOMOUS MONITORING & DETECTION
- Graph-based network simulation with 20+ nodes, 2 reservoirs
- Physics-driven pressure/flow calculations (Bernoulli's principle)
- Between-node anomaly detection (mid-pipe leaks via pressure differential)
- Asset aging tracking (pipes/valves/sensors with condition degradation)

AI-DRIVEN DECISION ENGINE
- Priority-based issue ranking (critical > warning > info)
- Multi-tier fallback strategies (valve adjust → tanker → reroute)
- Action success/failure tracking with intelligent retry
- Stability-based resolution (issues resolve only after verified improvement)

PREDICTIVE INTELLIGENCE
- Asset condition forecasting (days-to-failure estimates)
- Risk trend analysis (increasing/stable network health)
- Proactive stress reduction before failures occur
- Separation of predictive intelligence from operational alerts


4. SYSTEM ARCHITECTURE
================================================================================

Frontend (React + Vite)
    ↓ User interactions, real-time visualization
Simulation Engine (WaterFlowEngine.js)
    ↓ Physics calculations, network state management
AI Layer (AutoFixEngine + PriorityEngine)
    ↓ Issue detection, prioritization, action execution
Backend (Supabase)
    ↓ Authentication, persistent storage, real-time sync
Database (PostgreSQL via Supabase)
    ↓ Issues, complaints, tankers, infrastructure metadata

SIMULATION LOOP (500ms tick):
1. Update zone demands (time-of-day multiplier)
2. Propagate pressure through network (3 iterations)
3. Calculate flows through pipes (blocked pipes = 0)
4. Update zone supply (network + tanker contributions)
5. Detect anomalies (pressure imbalance, under-supply, leaks)
6. Execute AutoFix actions (valve adjustments, tanker dispatch)
7. Monitor action outcomes (stability checks)
8. Age assets (pipes/valves/sensors degradation)

7. AI INTELLIGENCE SYSTEM
================================================================================

PRIORITY ENGINE
- Ranks issues by: (severity weight × 10) + (confidence / 10)
- Critical issues (severity=critical) processed first
- Prevents action spam on low-priority alerts

ACTION TRACKER
- Records every action attempt (success/failure)
- Prevents duplicate actions within 30 seconds
- Tracks improvement metrics (pressure recovery, supply increase)

FALLBACK STRATEGIES
- Multi-tier action selection per issue type
- Example for UNDER_SUPPLY:
  1. Open nearby valve (+20%)
  2. Dispatch tanker
  3. Reroute surplus from other zones
- Example for ASSET_AGING:
  1. Reduce pressure on aging pipe (-20%)
  2. Reroute flow away from critical asset

STABILITY-BASED RESOLUTION
- Issues require 3 consecutive stable ticks before marking "resolved"
- Prevents premature resolution from temporary fluctuations
- Failed actions trigger fallback retry with different strategy

LIFECYCLE TRACKING
- detecting: Initial detection phase
- validated: Confirmed issue ready for action
- in_progress: AutoFix action executing
- resolved: Issue stabilized and verified


8. WATER QUALITY & TREATMENT
================================================================================

CONTAMINATION DETECTION
- pH monitoring on all 20 nodes (every 5 seconds)
- Unsafe thresholds: pH < 6.5 or pH > 8.5
- Automatic spread modeling to connected pipes and zones

ISOLATION & REDIRECTION
- Contaminated zones isolated from main network
- Flow redirected to treatment plant (50% of zone supply)
- Visual indicators (red dashed pipes, "isContaminated" flag)

TREATMENT PLANT SIMULATION
- Capacity: 2000 L/min
- Current load tracking
- Efficiency: 85-90%
- Processing time: 8 seconds (realistic delay)

SAFE WATER REINTEGRATION
- pH normalized to 7.0
- Zone status: unsafe → safe
- Pipe contamination flags cleared
- 5-second restoration delay
- Quality status propagated to connected nodes

12. HOW IT WORKS (STEP-BY-STEP FLOW)
================================================================================

OPERATIONAL CYCLE:

1. SENSOR DETECTION
   - Node pressure sensors read PSI values
   - Pipe flow sensors measure L/min
   - Water quality sensors check pH/turbidity

2. ANOMALY DETECTION
   - Between-node pressure differential analysis (leak detection)
   - Flow drop analysis (blockage detection)
   - Asset condition monitoring (aging detection)

3. ISSUE CREATION
   - Issue object created with type, severity, confidence
   - Location identified (node ID, pipe ID, or N1-N2 segment)
   - Lifecycle initialized to "detecting" → "validated"

4. AI PRIORITIZATION
   - Priority Engine ranks by severity × confidence
   - Highest-priority issue selected for action
   - Lower-priority issues queued

5. AUTOFIX EXECUTION
   - Fallback strategies retrieved for issue type
   - First strategy attempted (e.g., valve adjustment)
   - Action applied to engine (valve.openPercentage updated)
   - Action status: executing → completing → completed

6. SYSTEM STABILIZATION
   - Monitor pressure/flow recovery over 3 ticks (9 seconds)
   - Verify improvement (e.g., pressure increased by 10 PSI)
   - Mark issue "resolved" if stable

7. DATA LOGGING
   - Issue logged to Supabase with timestamps
   - Action outcome recorded (success/failure)
   - Analytics updated (efficiency, alert counts)
